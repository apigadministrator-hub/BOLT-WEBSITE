# API GROUP CONTENT HIERARCHY AND SAMPLE DATA

## PURPOSE

This document defines the initial content hierarchy and demonstration data for API Group.

The purpose is to create enough structured sample content to demonstrate how the API Group website will actually function when populated with real information.

The sample data is not production content.

It exists to demonstrate:

- Hierarchy
- Categories
- Subcategories
- Dependencies
- Records
- Profiles
- Articles
- Images
- Search
- Cards
- Directories
- Sidebars
- Breadcrumbs
- Relationships
- Database-driven navigation
- Administrator editing
- AI-assisted data entry
- Infinite expansion

All sample content must be clearly identified as demonstration/filler content.

---

# 1. API GROUP IS A DATABASE-DRIVEN COLLECTION

API Group is not a collection of individually hard-written webpages.

The website should display records stored in the database.

The same record may appear in multiple places.

For example:

A county record may appear:

- In a county directory
- In a sidebar
- In a search result
- On a profile page
- In an article relationship
- In a related-record section

These are different presentations of the same database record.

Do not create duplicate records simply because the record appears in multiple locations.

API GROUP

# 58. AI-ASSISTED RECORD CREATION

The system should eventually allow AI to create structured records.

Example:

AI receives information about a new county.

AI should be able to:

1. Determine whether the county already exists.
2. Create the county record if it does not.
3. Add the description.
4. Add the image if supplied.
5. Establish relationships.
6. Make the record available to the website.

---

# 59. AI-ASSISTED CATEGORY CREATION

# 60. AI MUST NOT WRITE STATIC NAVIGATION
